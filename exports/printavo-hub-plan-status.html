Printavo Hub — Detailed Plan, Status & Roadmap

The Hub has moved beyond a collection of ports into a working internal operating platform: shared Printavo data, sales intelligence, customer context, purchasing, production, quoting, shipping, loyalty, communications, AI support, and backups in one staff-controlled system.

Where we are now

The foundation and most core tools are built. The next phase should not be “build everything.” It should be a focused team review: identify the few workflows that save the most time or improve the most decisions, validate them with real staff use, and dial those in before expanding the surface area.

Executive status

Operational foundation

Sync, identity, access & module shell

Staff login, module access, shared Printavo mirror, global sync visibility, route isolation, and a unified navigation system are in place.

Core workflows built

Purchasing, production, quoting & shipping

Vendor ordering, PO tracking, print queues, pricing, shipping estimates, label sorting, and supporting automation have substantial working implementations.

High-value tools evolving

Customer, sales, email & AI intelligence

Client 360, pipeline, correspondence, knowledge, voice profiles, Ask AI, and AI quote drafting are available and should now be shaped by team feedback and measured use.

Operational decisions

Controlled automation and go-live settings

Some write paths and outbound emails intentionally remain guarded, test-routed, dry-run, or single-owner until Tyler explicitly approves live operation.

Punch list — specific items waiting for testing or input

A. Waiting for Tyler or a teammate to test

  1. Choose and test the 3–5 highest-impact daily workflows.

    Invite one representative teammate to use the Hub without coaching. Record where they hesitate, leave the Hub, distrust the data, or cannot identify the next action.

    Suggested choices: Sales—Pipeline, Customer Profile, Correspondence, Product Finder. Purchasing—Vendor Orders, PO Log, Tracking. Production—Print Queue, Queue Rules, Auto-Print. Quoting—Price Calculator, AI Quote Drafts.
  2. Reorder Portal end-to-end acceptance.

    Confirm the customer experience and internal staff handoff.

    Test: open /reorder/ → search by a real customer email and company → verify order history, dates, filters, line items, sizes and prior quantities → change quantities → enter test contact details → submit → open Hub /reorder-requests → expand it → move New → In Progress → Done. Confirm the outbound email destination and test/live routing. Submission does not create a Printavo invoice.
  3. Chipply Store import acceptance (CH1).

    The next Chipply phase remains gated by acceptance of the current import and linking workflow.

    Test: paste a representative “Web Store Closed” email → review/edit every parsed field → save → verify store detail → confirm correct $0 Printavo shell matches → verify Chipply dollars remain separate from Printavo revenue.
  4. Production print workflow acceptance.

    Validate the physical result and recovery path, not only the screen.

    Test: with order #22251 only, run a manual Print Queue preview, verify attachments and exclusions, inspect Mint packing-slip/box-label output, then validate PrintNode in dry-run or ask mode. Confirm duplicate protection and intended status movement.
  5. Shipping workflow acceptance.

    Confirm the tools match the packages and documents staff actually handles.

    Test: compare rates for a known shipment using actual box presets/address paste; upload a representative packing-slip/USPS-label set into Label Sorter and verify pairing, sort order and match report.
  6. Client 360 and sales workspace acceptance.

    Confirm customer profiles surface needed context without bouncing among Printavo, inboxes and spreadsheets.

    Test: find a known customer → inspect spend, contacts, orders, top styles, decoration mix, niche, artwork/brand sheet, Chipply context and authorized correspondence → note the three facts/actions that should be most prominent.

B. Waiting for Tyler’s scoring or product decision

  1. Score the 50 AI quote backtest drafts. Current blocker

    The backtest task is in progress but waiting for input. Record Keep/Drop and, where useful, a reason. This evidence should determine which drafting patterns deserve refinement.

  2. Select the team’s 3–5 “must-win” workflows.

    Rank by frequency, hours saved, error/risk reduction, revenue/customer impact and likely adoption. This decision should control the next refinement cycle.

  3. Decide Mint Bucks live-email and poller ownership.

    Choose whether the Hub or standalone app owns polling, turn the other poller off, set live email mode only in the intended environment, restart and test carefully. Manual/test polls can consume one-shot ledgers.

  4. Decide Printavo ⇄ moMINTum automatic sync ownership.

    The automatic sync flag may be enabled in one environment only. Confirm development or production ownership—never both.

  5. Approve which guarded automations may move beyond ask/dry-run.

    Vendor submission, status rules, Print Queue rules, Auto-Print and Printavo task writes should be approved separately after the corresponding workflow test.

  6. Decide whether the Hub is ready to publish for broader staff use.

    Publishing should follow production schema verification, settings review, backup readiness and explicit ownership of pollers/email modes.

C. Waiting on outside input or an external audit

  • Fireflies visibility audit: determine what a Business Team Admin read-only key can see, especially private meetings, before choosing central versus per-user access.
  • Chipply automation answer: confirm whether scheduled export emails or a supported data feed can replace manual import. The current review/import workflow remains useful either way.
  • Carrier/vendor behavior: live rate, inventory, tracking and order behavior depends on connected providers; record exceptions by provider and workflow.

D. Operational readiness checks before relying on the Hub

  • Offsite backups: establish nightly independent copies with retention, visible success/failure, integrity checks and a practical restore/openability drill. Current export is valuable but is not a one-click Printavo restore.
  • Production database: verify all new Hub-owned tables exist before or during publishing.
  • Email modes: verify Reorder Portal and Mint Bucks destinations before customer-facing use; test routing should remain obvious and intentional.
  • Real-write guard: all Printavo write testing uses #22251 (“TEST DO NOT ORDER”) only. Never use #19004.

Recommended focus for the team review

  1. Choose 3–5 “must win” workflows.Ask each teammate where time is lost, where errors recur, and which information is hardest to find. Rank impact by hours saved, risk reduced, revenue influenced, and frequency of use.
  2. Run real workflow validation before adding breadth.Use the Hub on actual day-to-day work, capture friction at the page/action level, and distinguish missing capability from usability polish, data quality, or training.
  3. Dial in the customer and sales workspace.Directory, profiles, pipeline, correspondence, reorder requests, and product curation can become the team’s daily front office if the views, filters, ownership, and next actions match staff habits.
  4. Dial in production and purchasing reliability.Vendor Orders, PO Log, tracking, Print Queue, queue rules, and auto-print have direct operational leverage. Validate handoffs, exception handling, safeguards, and ownership.
  5. Prove AI value with narrow, reviewable tasks.Complete the quote-draft scoring exercise, keep knowledge learning human-approved, and prioritize repeatable answers/drafts over broad autonomous behavior.
  6. Finish operational readiness.Verify offsite backup copies and restoreability, production schema, deployment settings, poller ownership, and test/live email controls before depending on the Hub as critical infrastructure.

Detailed module status

Foundation — Printavo mirror, sync and access

Built

The shared foundation mirrors Printavo data into PostgreSQL for faster reporting and safer cross-module use. Recent activity is polled frequently; deeper checks and historical processes fill the longer-term record. Every Hub page receives global sync visibility. Staff identity, allowlisting, roles, module availability and administrative controls support staged rollout.

  • Sync, normalization, hashing, change events, run state, retries and freshness indicators are implemented.
  • Module visibility allows independent rollout; email data has additional role/group/thread controls.
  • Printavo lacks a true updated-since feed, so the sync uses bounded recrawls and deeper scheduled verification.

Dashboard, Reports and Payments

Staff validation

The Dashboard provides orientation and shortcuts. Reports and Payments expose local order, revenue and cash-history data without repeatedly querying Printavo. The technical foundation is present; the remaining work is deciding which metrics, saved reports and exceptions matter most by role.

Next: collect each reviewer’s three most frequent business questions and convert only recurring ones into reports or presets.

Ask AI, Knowledge Base, AI Connections and Voice Profiles

Evolving

Ask AI turns plain-English questions into guarded read-only queries. Knowledge Base stores human-approved SOPs and reference knowledge. AI Connections governs consumers, auditing, rate limits and kill switches. Voice Profiles support appropriate drafting.

  • AI answers remain read-only and reviewable.
  • Quote and correspondence drafting assist rather than autonomously send.
  • Conversation learning is proposed but must remain draft-first and human-approved.
  • The 50-draft scoring exercise is the immediate evidence gate.

Email Activity, Email Access and Correspondence

Evolving

Authorized mailbox activity and customer correspondence can be viewed in the Hub. Admins manage broad visibility while managers/staff are limited by mailbox groups, ownership or explicit thread grants. Customer context aggregates only correspondence the user is authorized to retrieve.

Next: validate customer matching, access boundaries, thread summaries and next actions before adding more communication channels.

Client 360 — Directory, profiles, brand sheets and niches

Staff validation

The client workspace consolidates customer search, lifetime/YTD spend, frequency, average pieces, top styles, decoration mix, order history, contacts, niches, Chipply context, brand/artwork and authorized correspondence. Niche tools support inline/bulk assignment and segment reporting.

Next: decide the default profile hierarchy and which facts should trigger a follow-up, recommendation or warning.

Sales — Product Finder, Pantones, Collections, Pipeline and Status Activity

Evolving

Product Finder searches vendor catalogs and live inventory; Pantones supports color decisions; Collections saves curated products; Pipeline and Status Activity show active work and movement. Together these can become the daily sales workspace.

  • Inventory remains live rather than cached.
  • Catalog corrections and shared color data should survive refreshes and later serve other Mint tools.
  • Collections can later support sell sheets, customer links, calculator handoff or separately reviewed Printavo writes.

Next: staff feedback on saved views, ownership, filters, product comparison and next actions.

Chipply Stores

Tyler test

CH1 imports “Web Store Closed” emails through required review, stores Chipply financials separately, detects candidate Printavo groups and derives links to $0 production shells. Chipply dollars never mix into Printavo revenue.

After acceptance: customer-profile context, separate reporting, CSV imports, customer reassignment and potentially hands-off ingestion.

Public Reorder Portal and Hub Reorder Requests

New · test

The customer-facing portal supports no-login email/company lookup, eligible prior-order browsing, quantity selection, request submission and shareable saved-search URLs. Hub staff manage requests through New, In Progress and Done.

  • Writes re-validate invoice eligibility and line-item ownership.
  • Share links are saved public searches, not private authenticated links.
  • Submission stores/emails a follow-up request; it does not create a Printavo invoice.
  • Private links, check-in/verification and invoice creation are deferred pending feedback.

Purchasing — Vendor Orders, PO Log, Tracking and Status Rules

Built

Purchasing covers needs-ordering discovery, SanMar/S&S pricing and inventory, cart and warehouse selection, PO creation, guarded Printavo updates, electronic vendor submission, tracking and confirmed status suggestions. Both vendor paths have live verification and duplicate/ambiguous-result safeguards.

Open: staff exception validation and workflow polish. “Reorder Scan” is a separate deferred placeholder—not the customer Reorder Portal.

Production — Print Queue, Queue Rules, Auto-Print, packing slips and labels

Tyler test

The suite supports filtered workorder preparation, presets, exclusions, attachments, bulk status moves, off/ask/auto rules, PrintNode auto-print, duplicate protection and Mint-rendered packing slips/box labels.

Current posture: safety-first. Validate output and exceptions with #22251 before broader automation. Color Library remains deferred.

Quoting — Price Calculator and AI Quote Drafts

Evolving

Price Calculator provides matrices, CSV import, vendor costs, legacy-compatible math, detailed breakdowns and image export. AI Quote Drafts prepares reviewable customer, pricing, note and matrix drafts.

Next: finish keep/drop scoring and improve proven patterns before any expansion toward automatic quote creation.

Team — moMINTum and Printavo task sync

Ownership decision

The Hub links to moMINTum, sharing the standalone app’s live database. Printavo task twins support routing, two-way completion, deletion reconciliation and guarded send-to-Printavo.

Hard rule: automatic task sync may run in one Hub environment only. Choose development or production ownership.

Shipping — Rate Estimator and Label Sorter

Staff validation

Rate Estimator compares USPS/UPS options using weights, packages and address parsing. Label Sorter organizes packing slips by configurable fields and pairs USPS labels one-to-one with a match report.

Next: validate real package profiles, carrier responses and production sorting sequences.

Mint Bucks

Go-live decision

The complete store-credit module includes dashboard, customers, credits, redemptions, reward rules, branded emails, reports, certificates, balance check and settings. It shares live data with the standalone app.

  • Email is controlled by test/live mode.
  • Only one app owns polling; stop the old owner before starting the new.
  • Manual/test polls can consume shared one-shot claims.
  • Never schema-push the shared Mint Bucks database.

Backups and recovery

Strengthen

The Hub creates a broad portable Printavo archive, including historical records and accessible mirrored files. This improves recoverability but does not restore directly into Printavo.

Next: dated offsite copies, retention, failure visibility, integrity verification and a written restore drill.

Questions for Tyler after the team review

  • Which three pages would the team use every day?
  • Which workflow currently wastes the most labor?
  • Where would a mistake be most costly?
  • Which data or answer is hardest to find today?
  • Which automation feels safe enough to enable?
  • What should be hidden until it is more mature?
  • Which module needs better defaults, not more features?
  • What result would prove the Hub is paying off?

Non-negotiable operating rules

  • Build and validate incrementally; avoid a big-bang rollout.
  • Keep modules independently tunable so one tool cannot destabilize another.
  • Use Printavo order #22251 only for real-write testing; never use #19004.
  • Non-idempotent vendor/Printavo writes get one attempt; ambiguous results require manual verification.
  • Only one environment may own Printavo ⇄ moMINTum polling.
  • Only one app may own Mint Bucks polling; test emails can consume one-shot ledgers.
  • AI knowledge changes remain draft-first and human-approved.
  • Customer correspondence access must be enforced before retrieval, not only hidden in the UI.
