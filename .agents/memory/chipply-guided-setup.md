The Chipply setup guide is optional and reuses the existing import, reconciliation, and category approval tools. Its progress is shared per store, not private to a browser.

**Why:** The user requested one beginning-to-end workflow because the separate tools made it difficult to know what was actually finished.

**How to apply:** Keep user confirmations distinct from machine-verified facts. Navigation never verifies data. Relevant source changes invalidate prior confirmations; incomplete evidence must remain visible even when staff continue. Preserve explicit approval for replacing detailed snapshots and writing Printavo categories. Scope guided uploads and invoice category selection to the selected store; do not silently route a mismatched file to another store.

The user found that getting the full Chipply picture requires roughly three or four exports, not one comprehensive report. The multi-store summary grid has no usable export for them, but they confirmed that copying and pasting it into a CSV works.

**Why:** Their attempt to work through the guide exposed fragmented source information.

**How to apply:** Do not assume a single export supplies all setup evidence. Prefer the confirmed copy/paste CSV path over screenshot OCR for the summary grid.

Store Summary ingestion is approved strictly for filling blanks: “we do not want this report to overwrite anything, however it can flag discrepancies for decision.” The user will upload the supplied file in the live app after republishing; do not pre-import it while building.

**Why:** Existing store data must not be replaced by a less detailed summary source.

**How to apply:** Preserve populated values, including zero; show differences for explicit decisions. Keep the summary's Sales separate until its definition is confirmed against other Chipply financial measures. Do not coerce Catalog Batch identifiers into numeric Group-store identities.
