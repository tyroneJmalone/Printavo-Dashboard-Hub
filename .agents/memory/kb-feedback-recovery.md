---
name: KB feedback and source recovery
description: Human-review boundaries and safe recovery identity for imported brand guidance.
---
Playground feedback is explicit staff-submitted evidence, not an authoritative model run or a source of automatically approved knowledge. Preserve its response/source snapshot and attribution; marking it reviewed must not promote a correction.

**Why:** The user approved a feedback-and-review workflow, not automatic learning or widening access to knowledge. Test messages should remain ephemeral unless feedback is explicitly saved.

Recovery previews must bind to the document version and be rechecked under the commit lock. Deduplication must depend on source provenance rather than generated wording or the current edited entry body.

**Why:** Review found that changed source documents could invalidate previews, and model paraphrases or approved editorial changes could create duplicate recovered guidance.

**How to apply:** Keep recovery additive, preserve approved entries, and make identity-granularity limitations visible. Preserve date-qualified source content; if exact applicability cannot be established, retain an internal review draft rather than discarding content or treating it as evergreen guidance.
