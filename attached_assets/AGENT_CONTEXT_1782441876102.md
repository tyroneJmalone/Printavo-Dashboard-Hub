# Vendor Order Submission App — Agent Context

This document describes the architecture, data model, and integration details of the **SanMar Order Submission** app built on Replit. It is intended to help a planning agent understand the system before combining it with other Printavo-connected apps into a unified dashboard.

---

## What This App Does

This is a **vendor purchase order management tool** for a print shop. The core workflow is:

1. Import a purchase order from Printavo (by browsing unordered POs or entering a PO number manually)
2. Fill in or confirm line items (style number, color, sizes/quantities, warehouse)
3. Submit the order to a vendor (SanMar or S&S Activewear) via their respective APIs
4. Track the order status and retrieve shipping/tracking info

## Vendor Integrations

### SanMar (SOAP/XML)
- **Protocol**: SOAP XML, authenticated with username + password + customer number
- **Key operations**:
  - `GetProductInfoByStyleColorSizeQty` — inventory check per warehouse
  - `SubmitOrder` — places the order, returns a SanMar order number
  - `GetOrderStatus` — refreshes status and tracking numbers
- **Warehouses (9 locations)**: Seattle WA, Cincinnati OH, Dallas TX, Reno NV, Robbinsville NJ, Jacksonville FL, Minneapolis MN, Phoenix AZ, Richmond VA

### S&S Activewear (REST JSON)
- **Protocol**: REST JSON API, authenticated with API key + account number
- **Key operations**:
  - SKU resolution by style number + color name
  - Order submission
  - Status/tracking refresh
- **Warehouses**: IL, NV, GA, KS, TX, FL, OH, PA, DS, CC, CN, FO, GD, KC, MA, PH, TD

## Printavo Integration Details

### Auth
- Endpoint: `https://www.printavo.com/api/v2`
- Auth headers: `email` and `token` (not Bearer token — raw header values)

### GraphQL Schema Path to Purchase Orders
```
invoices (or quotes)
  → nodes
    → lineItemGroups
      → nodes
        → lineItems
          → nodes
            → poLineItem       # PoLineItem — null when no PO attached
              → purchaseOrder  # PurchaseOrder
```

### PurchaseOrder Fields Used
| Field | Type | Notes |
|---|---|---|
| `id` | ID | Internal GraphQL node ID |
| `visualPoId` | ID | User-visible PO number shown in Printavo UI |
| `goodsStatus` | PoGoodsStatus | `not_ordered`, `ordered`, `arrived`, `partially_received`, `received` |
| `note` | String | Optional PO note |

### PoLineItem Fields Used
| Field | Notes |
|---|---|
| `id` | Used as anchor for detail fetches |
| `itemNumber` | Style number |
| `color` | Color name |
| `description` | Item description |
| `sizes` | `[{ size { name }, count }]` |

### Complexity Budget
Printavo enforces a **25,000 complexity limit** per query. The `invoices.first` field is hard-capped at 25 by the API.

Current stable browse config:
- `invoices(first: 25)` — 8 pages (covers 200 invoices)
- `quotes(first: 25)` — 8 pages (covers 200 quotes)
- `lineItemGroups(first: 8)` per order
- `lineItems(first: 15)` per group
- Estimated complexity: `25 × 8 × 15 × ~8 ≈ 24,000` (just under limit)
- Finds ~71 unique POs across ~350 total orders

### Browse Strategy (Two-Step)
1. **BROWSE pass**: Paginate invoices + quotes in parallel with a shared `seen` Set (deduplicates by PO `id`). Returns PO headers + the `lineItem.id` anchor for each unique PO.
2. **DETAIL fetch**: Uses `lineItem(id)` root query (no nesting multiplication) to retrieve full `PoLineItem` data including sizes.

### Filter Applied
The frontend only shows POs with `goodsStatus === "not_ordered"` or `goodsStatus === null` (null treated as not-yet-ordered). Already-ordered POs are hidden.

## Frontend — Key UI Flows

### New Order Form (`/orders/new`)
Three ways to populate an order:
1. **Manual entry** — type PO number, add line items by hand
2. **PDF upload** — drag-and-drop a vendor PDF; backend parses style, color, sizes, quantities
3. **Printavo import** — browse unordered POs from the dropdown or enter a visual PO number directly

Per line item:
- Vendor selector (`SanMar` / `S&S` / `Skip`)
- Style number + color name → triggers live inventory/pricing lookup
- Warehouse selector (populated based on vendor)
- Size/quantity grid (XS through 5XL)
- Real-time availability badges per size

### Dashboard (`/`)
- Lists all submitted orders, newest first
- Shows vendor, PO number, status, tracking
- Refresh button re-polls vendor for status updates
- Archive with optional note

## Known Constraints & Quirks

- **`vendor { name }` field on PurchaseOrder is broken**: Declared as `Vendor!` (non-nullable) in the schema but returns `null` in practice — including it causes a GraphQL error. Omit it.
- **No root `purchaseOrders` query** in Printavo's v2 API — must traverse from `invoices` or `quotes`.
- **`visualPoNumber` on Invoice** exists in the schema but is always empty in this account.
- **Printavo REST v1** (`/api/v1/purchase_orders`) returns 404 for this account.
- Some POs may be unreachable if they're attached to line items beyond the group/item limits (>8th group or >15th item in a group).
- The `goodsStatus` field exists **only on PurchaseOrder** — not on `LineItem` or `PoLineItem`.
