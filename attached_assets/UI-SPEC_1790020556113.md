# PrintScope — interface specification

**Status:** this describes the interface as built and as corrected through use
by Mint's art team. It is not a wishlist. Several behaviours here replaced an
earlier, more obvious version that turned out to be wrong in practice — those
are called out in §9, and re-deriving them from first principles will land you
back on the version that was rejected.

**Reference implementation:** `build_site.py` in the engine bundle generates
this interface. Where this document and that file disagree, the file is right.
Read it alongside this spec; between them there should be no ambiguity.

**Data contract:** `SCHEMA.md`. The interface renders a verdict; it never
computes one.

---

## 1. What this screen is for

One job: **a person with no design software and no prepress training decides
whether a separation file goes to the press floor or back to the vendor.**

Everything follows from that. The verdict leads. The artwork is evidence, not
decoration. The rule detail exists so the person can say *why* in words a press
operator understands, not so they can admire the analysis.

This is a tool that gets operated, not a document that gets read. Surface the
summary before the detail; encode state in form as well as colour.

---

## 2. Three states, and what they mean

| State | Words shown | Meaning |
|---|---|---|
| `fail` | **Send it back** | A rule that must hold does not. The file is wrong. |
| `flag` | **Look at it** | The rule cannot decide from the file alone. A human call. |
| `pass` | **Clear to run** | Every rule that applies to this file passed. |

The file's overall verdict: any fail → fail; else any flag → flag; else pass.

**Yellow is not "minor red."** It means the tool has measured something and
genuinely cannot tell — a trap that may or may not be needed, a technique like
gradient blending or opacity that is deliberate but needs a press operator's
eye. Copy should never imply a yellow is a lesser fault. It is a different kind
of thing.

A fourth status, `skip`, means the rule could not be evaluated at all. **Never
present a skip as a pass.** It gets its own collapsed group.

## 4. Design tokens

Define all of these on bare `:root` as the light palette. Redefine only the
values under `@media (prefers-color-scheme: dark)` guarded by
`:root:not([data-theme="light"])`, and again under `:root[data-theme="dark"]`.
Never give a colour its only definition inside a media or theme block.

### Light

```
--paper      #F1F3F2    page ground
--surface    #FFFFFF    cards, rail, header
--surface-2  #E8ECEA    toolbars, hover, checkerboard
--ink        #14201D    body text
--ink-2      #4A5A55    secondary text

--line       #D3DAD7    borders
--line-2     #BDC7C3    stronger borders, control outlines

--fail       #A82520    --fail-bg  #FAE3E1
--info       #4A5A55    --info-bg  #E8ECEA
```

### Dark

```
--paper      #0E1614    --surface    #16211E    --surface-2  #1E2C28
--ink        #E4EBE8    --ink-2      #A6B5B0    --ink-3      #7A8983
--line       #2A3A35    --line-2     #3A4C46    --accent     #3FB3A3

--info       #A6B5B0    --info-bg    #1E2C28
```

The neutrals carry a slight green bias rather than being pure grey — it ties to
the accent and to Mint's own name. `body` must set an explicit background from a
token; a transparent body borrows the host's ground.

**Semantic colour is separate from the accent.** Teal means "selected". Green,
amber and red mean pass, flag and fail. Never use the accent for a verdict or a
verdict colour for a control.

## 5. Typography

Three roles, from Google Fonts, each with a real fallback stack.

| Role | Face | Used for |
|---|---|---|
| Display | **Archivo** 600/700 | headings, uppercase labels, buttons, status pills |
| Body | **IBM Plex Sans** 400/500/600 | rule headlines, prose |
| Data | **IBM Plex Mono** 400/500 | filenames, ink names, measurements, rule codes |

The mono face is not decoration. Ink names *are* codes — `5-230-Grey 428 C`
encodes head, mesh and colour — and they need to line up when stacked. Use
`font-variant-numeric: tabular-nums` anywhere digits column up.

Uppercase labels get `letter-spacing: .09em`. Base body size 15px, line-height
1.5.

## 6. Components

### 6.1 Header (sticky)

Brand mark (a 9px accent dot plus the name), a context line, and the legend:
three small swatches reading *send it back / look at it / clear to run*. The
legend teaches the colour language on first use and costs one row.

Sticky positioning uses `top: env(safe-area-inset-top, 0px)`, not `0`.

### 6.2 Queue rail

One row per inspected file, newest first. Each row:

- a 4px full-height severity stripe in the verdict colour — this is the scan
  target, and it works without relying on colour alone because position and
  count also carry
- filename in mono, truncated with ellipsis, never wrapped
- a meta line: `0F 0Y 20P` (fail / flag / pass counts) and the inspection time

Selected row: `surface-2` background, filename in accent, `aria-current="true"`.

Rail header shows the totals: *11 files · 0 failed · 1 flagged*.

### 6.3 Verdict banner

The largest thing on the screen. A 5px left border and a tinted background in
the verdict colour, the verdict words at 26px in the verdict colour, the
filename beneath in mono, then a tally row: *0 failed · 1 flagged · 18 passed ·
6 noted*.

Right-aligned meta, in mono and small: inspection timestamp, `sha` short hash,
file size. The hash matters — a file can change on disk between inspections, and
a verdict that cannot be tied to a specific version of the bytes is not evidence.

### 6.4 Plate viewer

This is the part that took the most correction. Read §9 before changing any of
it.

**Toolbar row:**
- `All stacked` tab, selected by default, then one tab per artboard. Base
  artboards are labelled `Artboard 2 · base`.
- `Colour` opacity slider, 10–100%, default 100
- `Base` opacity slider, 10–100%, default 100
- `Zoom` slider, 100–1600%, default 100 (= fit to width)

**Swatch chips row:** one chip per plate, showing a colour square and the ink
name in mono. Clicking toggles that plate's visibility; hidden chips go to 38%
opacity with a line through. In stacked view, chips are grouped by artboard with
a small `AB2 BASE` label and a hairline separator between groups.

**Stage:** a checkerboard ground so transparent areas read as empty rather than
white. Fixed height — `min(60dvh, 540px)` desktop, `min(52dvh, 400px)` mobile.
Scrolls in both axes when zoomed.

**Footnote line** under the stage, one line, stating what the view is showing:
whether artboards are stacked and what that means for reading trap, whether the
plates are vector or a raster fallback, whether knockout strokes were carved out.

### 6.5 Rule list

Grouped, with only the first group open:

1. **Needs attention** — fail and flag, fail first
2. **Passed** — collapsed
3. **Reported, not judged** — the info rows, collapsed
4. **Did not apply** — the skips, collapsed

Each row is a two-column grid: a 76px status cell tinted with the status
background and its uppercase status word, then the body — rule name in display
face, rule code in small mono, the headline at 14px, detail lines as a mono
list, and for fail and flag only, the remediation text in a left-bordered block.

Below 560px the status cell moves above the body.

When nothing needs attention, show a single row rather than an empty container:
*Every rule that applies to this file passed.*

**Closing note under the list**, always: the verdicts are the rule engine's
alone, no human judgement is folded in, and a yellow means the rule cannot
decide from the file and wants a person to look.

## 7. Interaction specification

### Stacking

In `All stacked`, every plate from every artboard renders into one canvas, in
print order: **underbase artboards first (bottom), then the rest by index.**
Sorting by artboard index alone is wrong — the base is usually artboard 2 and
would land on top of the colours.

Plates are keyed by **artboard index plus ink name**, not ink name alone. Two
artboards carrying the same ink must toggle independently.

### Opacity

Two independent sliders. The colour slider sets opacity on every non-base plate;
the base slider on base plates only.

Both directions are useful and neither is the "right" one:
- **Colour down, base at 100** — read the base through the colour body. Better
  for seeing where the base sits under a spread.
- **Colour at 100, base down** — the colour reads solid and the base ghosts
  beneath. Better for a choke, where the tell is a thin rim of colour with no
  base under it, and fading the colour dims the very thing you are hunting for.

### Zoom

Fit-to-width is 100%. The canvas gets a real pixel width (`stage.clientWidth ×
zoom`), so the stage scrolls rather than clipping. Do not use a CSS transform —
a transform leaves the scroll bounds wrong.

**Zooming holds the artwork, not the artboard.** Two parts:

1. On opening a file, centre on the art bounding box (`previews[].art` in the
   result JSON, already in display coordinates). The artboard is 16 inches wide
   and the design frequently sits off to one side — on one real file it is at
   75% across — so centring on the board lands you in empty space every time.
2. On every zoom change, capture the current viewport centre as a fraction of
   the canvas, apply the new zoom, then restore that fraction. Whatever was in
   the middle stays in the middle.

**The subtlety that breaks this:** at fit-to-width nothing scrolls, so the
"current centre" is just the middle of the board. Reading it there throws away
the art focus before the first zoom. Capture an axis **only when that axis can
actually scroll** (canvas dimension > stage client dimension). Otherwise keep
the existing focus value.

Canvas height is zero until the first image decodes, so re-run the fit and the
centring on that image's `load` event.

### Scale

Trap is 0.375pt of net inset — about 1/200th of an inch. At fit-to-width it is
sub-pixel; at 400% it is roughly one pixel. Reading it visually needs 600–1200%
plus an opacity slider. **The numbers in the rule panel are the measurement; the
picture is confirmation.** Any copy about the preview should preserve that
relationship rather than implying the eye is the instrument.

## 8. Responsive and accessibility

- Works at 400px wide. No horizontal page scroll; only the stage scrolls
  sideways, inside its own container.
- Side gutter ≥16px at every width, set once on an outer wrapper with
  `padding-block` for vertical space, never a `padding` shorthand that zeroes
  the sides.
- Selecting a file on mobile scrolls the detail panel into view.
- Visible focus ring on every control: 2px accent, 2px offset.
- Toggles use `aria-pressed`; the selected queue row uses `aria-current`.
- Status is never carried by colour alone — the status word is always present.
- Honour `prefers-reduced-motion`.
- The iPad case is the real one. The art team works from iPads on the floor.

## 9. Behaviours that were corrected through use — do not re-derive these

Each of these replaced a more obvious first attempt that the art team rejected
or that measurement proved wrong.

1. **Artboards stack by default.** The first build used exclusive artboard tabs.
   You cannot inspect a trap that way — the whole point is seeing the base
   under the colour.
2. **Two opacity sliders, not one.** One slider assumes you know which layer the
   user wants to fade. For a choke and a spread the answers are opposite.
3. **The base is never faded by the colour slider.** Keeping the base solid
   under faded colour is what makes the trap readable at all.
4. **Zoom centres on art, not artboard.** See §7. This was the single most
   common complaint before it was fixed.
5. **Plates are vector, not raster.** The source files are vector; a raster
   preview goes sawtoothed exactly when you zoom in to inspect an edge. A plate
   too dense for vector falls back to 600dpi raster, and the footnote says so.
6. **Ink colours come from the file, not from the swatch name.** Name-guessing
   rendered a green plate red.
7. **Layer placement is not a defect.** An early version flagged art sitting on
   the `Reg Marks & Info` layer. It is simply wherever the artist pasted, and
   about half of real files do it. Do not reintroduce a warning for it.
8. **Rule detail is collapsed by default except for what needs attention.** A
   25-row rule list open by default buries the three rows that matter.

## 10. Out of scope for this screen

Noted so nobody builds them speculatively:

- Editing or annotating the file. PrintScope is read-only, always.
- Side-by-side revision comparison. Wanted eventually; not specified here.
- Printing. The art team works from iPads; a shareable link beats paper.
- Any control that lets a viewer override a verdict. If a rule is wrong, the
  rule table changes — that is the whole design.
